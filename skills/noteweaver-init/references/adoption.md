# 已有 vault 接入

适用于普通 Obsidian vault，以及已初始化但仍有未接入笔记的实例。完成条件是选定范围的逐文件结果可核对，接入的知识通过检查，原文和链接的处理有记录。

## 盘点与范围

以 `onboard` 的 inventory 为入口，按目录和类型阅读代表性笔记，再检查拟接入的每个文件。报告包含精确路径、原有 title/type/class、frontmatter 和 Claim 解析错误、候选知识页缺失的 frontmatter 属性、命名问题与重名组；它不做完整内容校验。目录绑定只作用于当前目录，子目录需要单独处理。

区分知识笔记、原始材料、附件、日记、模板、导航和其他插件管理的内容。记录正文链接、wikilinks、嵌入、frontmatter 关系和外部资源引用。`unmanaged` 表示未纳入当前配置，不能据此把笔记丢弃或声称已合规。附件列表 `otherFiles` 只是其他可见文件，是否属于证据要阅读和核对。

根据用户目的给出收录与排除范围：已有授权足够时继续；类别、合并或范围确实需要人决定时，呈现具体文件和可选方案。支持逐步接入，不要求日记、模板等无关内容变成知识页。

## 制定可执行计划

选择适合现有库的方式：

- 保留原笔记，在 pages 中建立有来源的知识页。旧笔记是原始材料，接入结果链接到原文或其证据快照。
- 转换选定原笔记并移动到 schema 规定的位置。先保存原文快照或可恢复的版本，再通过 Obsidian 移动和更新引用。

默认优先保留原文。用户已授权整体迁移时按授权执行。混合内容可拆分为多个知识单元；同一对象已有页面时补充该页。目录或 tags 只能作为线索，类别以内容和实例词表为准。

为每个范围内文件记录：原路径、保留/接入/拆分/待审动作、目标路径与 kind/class、属性映射、证据来源、链接修复和完成状态。排除文件也登记理由。已初始化实例将计划及未决项存入配置的 review 路径；新实例在初始化前先形成可审阅计划，初始化后保存。存在未决项的记录使用 `status: open`；完成后更新状态并保留迁移记录。

核对目标 slug 在整个知识页目录的唯一性；冲突时确定合并或独立命名策略。新库 `paths.bank` 默认为 `pages`；已有实例按实际配置制定 [布局改造](layout.md) 计划，schema 的 kinds、directories 和 entity classes 保持一致。旧目录混有不同类别时，逐页规划目标位置，不能只给混合目录绑定一种类别。保留原 title；需要改名时保留有意义的 aliases。

先列出所需 schema 变更与已有属性对应关系，再按实例的授权和政策实施。属性值的放置由 schema 决定；带范围、时间、冲突或估计的值按 Claim 规则处理。正文中的已有数值、精度与单位保持可追溯。

## 分批转换

1. 核对 Git 工作区或保存可恢复快照，记录原文件路径和哈希。证据、已提交 Claim 不可变字段与人工核验记录按实例政策保留。恢复信息必须足以找回本批的原文、路径和链接。
2. 新实例按主 skill 的 `init` 预览并创建结构；已有实例复用现有配置。读取政策 README，以及本批需要的 pages、kinds、evidence、claims、attributes 和 navigation 规则。
3. 先做具有代表性的一批，覆盖普通笔记、关系链接和有来源的知识。按 [noteweaver-write](../../noteweaver-write/SKILL.md) 的要求接入原件、证据卡、页面与 Claim，再运行 `schema`、`index` 和 `check`。修正实际诊断后再扩大批次。
4. 使用真实材料建立证据。旧笔记中的 URL 不是已核验的证据卡；本地笔记可以按政策作为原始记录保存，但不能替代其转述的外部来源。缺少来源或可核对定位时，保留原文并登记待审；已获调研授权时调用 research 工作流补证据。agent 只登记实际完成的生成或核验，不把未查的事实或人工身份写成已核验。
5. 移动或改名使用运行中的 Obsidian 以更新原生链接；检查 frontmatter、正文、嵌入和 Claim 引用。Markdown 相对链接按目标目录重新计算。合并或删除需要实例政策与用户授权覆盖；先通过 `refs` 核对入链。
6. 每批记录完成的源文件、目标文件、证据、检查结果与未决事项，更新日志。重试前核对现有目标与记录，复用已完成页面和证据，避免重复收录。并发编辑发生时检查已经完成的部分，重新盘点后继续。

知识写入通过运行中的 Obsidian；连接失败先修复连接。恢复只处理本批已记录的文件，通过 Obsidian 还原路径和内容并重新检查。原始材料和已提交不可变证据保留，工具重装不能当作内容回滚。

## 完成与交付

再次盘点，核对计划中的每个文件：已接入的有目标与来源；保留或排除的有理由；待审的有具体缺口和 review 路径。检查迁移前后链接、附件及原文恢复信息，运行完整 `check` 和 `info`。check 只覆盖配置的知识页、evidence 等路径；库外文件的保留与排除由计划证明。

只有选定范围处理完、检查无错误且警告已交代时，才称该范围接入完成。有待审材料时明确已完成的范围和剩余项。交付接入/保留/排除/待审数量、目标路径、配置变更及验证结果，让后续 agent 可以从记录继续。
